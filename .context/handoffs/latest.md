# Передача менеджера MAX Desktop в новый чат — 26.10.2026

**Идентичность:** постоянный `manager_id=project-manager`, репозиторий `lvlaksim1/max-desktop`; менеджер сохраняет ответственность и намерения между чатами, новую сущность не создавать. Источник восстановления: `.context/ENTRYPOINT.md`, `.context/capsule.json`, `.context/manifest.json`, `.context/manager/state-integrity.json`. Обе авторитетные ветки `main`.

**Продукт:** Windows .NET 8/WPF, полный и обновляющий установщики GitHub Releases. Последний релиз **v0.1.8**, успешный CI 40255959364, выпуск 40255959472, Setup/Update/SHA-256 опубликованы. Новую версию не выпускали.

**Обязательные требования владельца:** только вход по телефону/SMS (2FA при необходимости), **никакого QR**. Главное окно X→трей, «−»→панель задач, правый клик на значке трея→«Выход», повторный запуск активирует старое окно вместо копии, обновитель завершает процесс; код реализован, полная пользовательская приёмка не подтверждена. Существующие данные аккаунтов хранить защищёнными средствами Windows.

**Сетевая архитектура:** TCP/TLS и WEB/WebSocket JSON v11 через .NET и Chromium/WebView2, автоматический выбор Edge→.NET→TCP до возможной отправки SMS; не дублировать запрос кода при неопределённом ответе. Внешние проверки GitHub Windows успешно получали анонимный INIT, но **это была другая сеть**.

**Ключевой инцидент:** на машине пользователя v0.1.8 TCP (9 попыток) даёт EOF до сертификата; WebSocket .NET даёт WS_CONNECT/TLS-EOF; Chromium/Edge — WS_CONNECT до открытия. Независимая проверка подтвердило тот же отказ **вне приложения**: Яндекс Браузер «соединение было неожиданно прервано» при открытии ws-api.oneme.ru, системный `curl.exe -I --max-time 15 https://ws-api.oneme.ru/websocket` выдаёт `curl: (35) schannel: failed to receive handshake, SSL/TLS connection failed`. Телефон/SMS не передавались, AUTH_REQUEST не проверен. Общая зависимость — инфраструктура `oneme.ru`; **точная причина обрыва не установлена** (маршрут/DNS/прокси/VPN/фильтрация/система/сервер).

**Контрольная проверка Windows Runner 26.10.2026:** повторные испытания TCP (40248116311), .NET WebSocket (40253115470), Chromium (40255463057) прошли успешно. На том же HTTPS-адресе ws-api.oneme.ru/websocket и методе HEAD утилита curl.exe на Runner вернула exit=0/HTTP=403 (40315701059); локальный ПК владельца ранее давал curl (35). Приоритетный следующий шаг не меняется: тот же компьютер через альтернативную независимую сеть. Выпуск остался v0.1.8.

**Ошибка прежней стратегии:** последовательно меняли TLS, прокси, IP и транспорт без независимой диагностики с пользовательского ПК. Не повторять; внешняя удачная сборка и INIT не являются успешной локальной приёмкой.

**Единственный приоритетный следующий опыт:** использовать **тот же компьютер через другую независимую сеть**, например мобильную точку доступа, выполнить `curl.exe -I --max-time 15 https://ws-api.oneme.ru/websocket`. HTTP-ответ (включая 400/403) доказывает HTTPS/TLS; ошибка 35 означает повторный обрыв. Сопоставить оба маршрута, затем принять адресное исправление. **Не создавать v0.1.9 вслепую.**

**После восстановления соединения:** реальное подтверждение INIT, SMS, код, 2FA, LOGIN и затем чаты, сообщения, вложения, уведомления; не выдавать заглушки за готовое. Подробная история: `docs/protocol/network-root-cause-2026-10-26.md`.

**Новое обязательное требование владельца (26.10.2026):** системный VPN остаётся включённым, отключать его нельзя. Решение для MAX Desktop должно работать с VPN; не предлагать тест с выключением.

**Локальный исполнитель подключён:** приватный `lvlaksim1/pc-runner-gateway` через стандартные Issue-задания на self-hosted Windows PC, разрешён клиент `lvlaksim1/max-desktop`, установлен официальный комплект `.pc-gateway/`. Подтверждены заявки №392, 393. Диагностика №394–398: две IPv4-записи MAX, TCP 443 работает, системный HTTP-прокси в loopback на процессе Xray, TUN; CONNECT даёт 200, но TLS для адресов ws-api.oneme.ru/web.max.ru завершается curl 35 даже при TLS 1.2/1.3. Контрольные домены через тот же прокси дают HTTP 200. Установить конкретное ограничение на маршруте VPN/выходе/стороне MAX пока не удалось; управляющее приложение Xray не определено.

**Следующий шаг:** только read-only изучение выбора маршрута Xray и адресных правил. Не менять VPN/прокси/маршруты без согласования. До реального HTTPS/TLS на ПК владельца протокол SMS/LOGIN не проверять. Новую версию приложения не выпускали; последняя v0.1.8.
