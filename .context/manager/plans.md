# MAX Desktop — текущий план (26.10.2026, после v0.1.10)

1. Не возвращаться к проблеме TLS: на снимке пользователя v0.1.9 подтверждён SESSION_INIT через физический интерфейс при включённом VPN. Ничего в настройках VPN не менять.
2. Обновить установленную v0.1.9 до v0.1.10 кнопкой «Обновить» или установщиком поверх существующей установки. Выпуск: https://github.com/lvlaksim1/max-desktop/releases/tag/v0.1.10. GitHub Actions release 40325831275 успешен.
3. Выбрать «Автоматически (сначала физический интерфейс)», нажать «Получить код» **один раз**. В прежней версии сервер отказал на WS_AUTH_REQUEST сообщением «Проверка не пройдена, попробуйте ещё раз».
4. При соответствующем серверном отказе новый протокол запрашивает CAPTCHA_REQUEST(224); приложение должно открыть человеко-решаемую VK Captcha, после её успешного решения передать captchaToken в запросе SMS. Это ещё не испытано на реальном аккаунте: если окно пусто/решение не определяется или сервер повторно отказывает — сохранить только текст безопасной диагностики, не передавать номер/код/токены. Не нажимать «Получить код» многократно.
5. Если запрос кода принят: ввод кода → 2FA при необходимости → подтверждённый LOGIN → сохранение и восстановление сеанса. QR не использовать.
6. После реальной авторизации завершить чаты, сообщения, вложения и уведомления, затем GUI-приёмку окна, трея, обновления и нескольких аккаунтов.
7. Исследования на конкретном ПК выполнять через частный pc-runner-gateway; не менять VPN, DNS, маршруты и системный прокси. Статус выпусков и значимые результаты фиксировать в капсуле с контрольными суммами.
