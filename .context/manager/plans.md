# MAX Desktop — текущий план (26.10.2026)

1. **Не повторять завершённые проверки.** На компьютере пользователя обычный браузер и `curl.exe` уже подтвердили ошибку TLS к `ws-api.oneme.ru`, независимо от MAX Desktop.
2. **Следующий контролируемый опыт:** подключить **тот же Windows-компьютер** через мобильную точку доступа либо другую независимую сеть. Выполнить без секретов:
   ```powershell
   curl.exe -I --max-time 15 https://ws-api.oneme.ru/websocket
   ```
   HTTP 400/403/404/426 тоже означает успешное HTTPS/TLS. Ошибка 35/Schannel означает, что соединение вновь оборвалось до HTTP.
3. Если на другой сети есть HTTP-ответ, изучить исходный провайдер/маршрут, DNS, прокси, VPN и фильтрацию; сравнить конфигурацию сетей. Если та же ошибка повторится, проверить общие компоненты компьютера (VPN/антивирус/сетевые фильтры/настройки TLS), но не объявлять их заведомо виновными. При необходимости отдельно проверить официальный MAX и реальные адреса/транспорт.
4. Только на основании установленного механизма отказа решить, требуется ли изменение MAX Desktop; **не выпускать v0.1.9 вслепую**. QR не предлагать. TLS-валидацию не отключать.
5. После рабочего TLS: анонимный INIT с компьютера пользователя → **один** запрос SMS → код → 2FA при необходимости → подтверждённый LOGIN; не публиковать номер, код, пароль, токен или Cookie.
6. Отдельно принять требования Windows-окна, один экземпляр и обновления. После авторизации — чаты и сообщения.
7. При существенных изменениях фиксировать доказательства в репозитории и обновлять все связанные файлы капсулы одним согласованным поколением и контрольными суммами.
