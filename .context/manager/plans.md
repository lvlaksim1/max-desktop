# MAX Desktop — план после публикации v0.1.17 (26.10.2026)

1. [Новая приёмка владельца] В v0.1.16 обычный чат уже открывается и настоящая история получена (пример 5 сообщений). Вылет возникал именно при выборе записи `chatId=0`. Это не проблема общего GET_HISTORY для обычных чатов.
2. [Исправлено] Запрос `MaxHistoryCodec.CreateRequest(0,...)` бросал `ArgumentOutOfRangeException`, не пойманный WPF. v0.1.17 проверяет `CanOpenChat` до обращения к серверу и отображает информацию вместо вылета; Windows smoke проверяет id=0.
3. [Новая функция] `ProtectedMaxAccountVault` хранит несколько отдельных сессий в DPAPI; импортирует одиночный старый файл, сохраняет выбранный аккаунт, поддерживает изолированные Store-слоты и удаление. MainWindow имеет список, добавление, переключение и удаление с подтверждением, не затрагивая другие аккаунты. Транспорт активного аккаунта меняется только после подтверждённого восстановления следующего сеанса.
4. [CI/release] Windows Actions 40366483307 — success, включая DPAPI-тесты; выпуск v0.1.17 GitHub Actions 40367266811 — success, обновляющий и полный установщики + SHA256, один последний релиз.
5. **Срочная приёмка:** обновить v0.1.16 до v0.1.17, проверить сохранённый аккаунт без повторного входа; нажать «Добавить аккаунт» и пройти SMS/2FA **только для нового** аккаунта; переключиться на первый и обратно, проверить списки, затем закрыть/перезапустить программу и повторить выбор. Клик «Чат 0» больше не должен завершать процесс. Данные переписок в публичные логи не записывать.
6. Только после пользовательской приёмки добавить последующие функции: подписи/названия аккаунтов, имена отправителей/групповые истории/пагинация, уведомления/вложения. **Отправка сообщений пока не нужна — указание владельца.**
7. Системный VPN включён и неизменен, QR/TinyFish запрещены, учетные данные/номер/чаты не публиковать.
