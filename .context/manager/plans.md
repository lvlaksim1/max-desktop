# MAX Desktop — план после v0.1.13 (26.10.2026)

1. Зафиксировано сравнение: оригинальный MAX **Android** позволяет владельцу вход без капчи/2FA; наш WEB v11 после SMS отвечает «Логин ограничен. Требуется установить 2FA». Это разные способы входа, но различие политики не доказано для новой сессии Android.
2. Добавлен самостоятельный вариант **TCP Android через физический интерфейс (VPN включён)**. Протокол основан на APK 26.35.1 и ранее реализованном нативном MAX; системный VPN, DNS, прокси и маршруты не меняются. Режим только явный, в автоматическое переключение после SMS не добавлен.
3. [ПК владельца, gateway #404] TLS всех трёх мобильных серверов прошёл с валидным сертификатом при работающем VPN. [Windows Runner #40345635857] Новый физический нативный транспорт подтвердил анонимный SESSION_INIT. [Windows CI #40345636022] Сборка успешна. [Release #40346233767] опубликована v0.1.13 и оставлена как единственный релиз.
4. **Следующее действие:** обновить приложение до v0.1.13, вручную выбрать «TCP Android через физический интерфейс (VPN включён)», нажать **«Проверить соединение (без номера)»**. При успехе INIT на этом же ПК — отдельная, один раз выполненная попытка входа с SMS. Не копировать и не публиковать номера, коды, токены, капчу и пароли.
5. Если сервер требует 2FA даже в мобильном режиме, принять это как факт отказа и исследовать поддерживаемый способ входа, а не менять идентификатор доверенного устройства для обхода защиты. Не объявлять LOGIN успешным до ответа сервера и восстановления DPAPI-сеанса.
6. После подтверждённого LOGIN — чаты, история и отправка, вложения, уведомления, несколько аккаунтов; GUI-приёмка окна, трея и обновителя.
7. Пользовательский VPN не отключать и не перенастраивать. ПК-испытания только через приватный pc-runner-gateway с закреплённым SHA, без TinyFish; проверки GitHub Actions выполнять без телефона/смс.
