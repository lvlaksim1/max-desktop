# MAX Desktop — план после публикации v0.1.17 (26.10.2026)

1. [Новая приёмка владельца] В v0.1.16 обычный чат уже открывается и настоящая история получена (пример 5 сообщений). Вылет возникал именно при выборе записи `chatId=0`. Это не проблема общего GET_HISTORY для обычных чатов.
2. [Исправлено] Запрос `MaxHistoryCodec.CreateRequest(0,...)` бросал `ArgumentOutOfRangeException`, не пойманный WPF. v0.1.17 проверяет `CanOpenChat` до обращения к серверу и отображает информацию вместо вылета; Windows smoke проверяет id=0.
3. [Новая функция] `ProtectedMaxAccountVault` хранит несколько отдельных сессий в DPAPI; импортирует одиночный старый файл, сохраняет выбранный аккаунт, поддерживает изолированные Store-слоты и удаление. MainWindow имеет список, добавление, переключение и удаление с подтверждением, не затрагивая другие аккаунты. Транспорт активного аккаунта меняется только после подтверждённого восстановления следующего сеанса.
4. [CI/release] Windows Actions 40366483307 — success, включая DPAPI-тесты; выпуск v0.1.17 GitHub Actions 40367266811 — success, обновляющий и полный установщики + SHA256, один последний релиз.
5. **Срочная приёмка:** обновить v0.1.16 до v0.1.17, проверить сохранённый аккаунт без повторного входа; нажать «Добавить аккаунт» и пройти SMS/2FA **только для нового** аккаунта; переключиться на первый и обратно, проверить списки, затем закрыть/перезапустить программу и повторить выбор. Клик «Чат 0» больше не должен завершать процесс. Данные переписок в публичные логи не записывать.
6. Только после пользовательской приёмки добавить последующие функции: подписи/названия аккаунтов, имена отправителей/групповые истории/пагинация, уведомления/вложения. **Отправка сообщений пока не нужна — указание владельца.**
7. Системный VPN включён и неизменен, QR/TinyFish запрещены, учетные данные/номер/чаты не публиковать.

## Новый этап: доказательная проверка платформы MAX
1. В v0.1.20 мини-приложение открывается, но сервер/сервис запрещает просмотр кодов вне мобильного приложения.
2. Вводится прозрачная диагностика: активный транспорт для выбранного аккаунта плюс WebAppPlatform из уже полученного серверного адреса. Не пытаться обмануть проверку через User-Agent/переписывание URL.
3. После выпуска диагностической v0.1.21 и успешной сборки выяснить значения двух полей по реальному нажатию «Посмотреть код». Случай WEB + web значит веб-сеанс/платформа; TCP + web значит разница сетевого протокола и окружения браузера; TCP + android с запретом указывает на отдельную серверную политику или доверенное устройство.
4. Для общего клиентского функционала исследовать поддерживаемые мобильные сценарии, но защищённые коды получать только через штатное доверенное устройство MAX. Не сохранять URL/коды и не менять системный VPN.
5. Сохранить принятую v0.1.17 (мультиаккаунты), v0.1.19 (сеть мини-приложений) и v0.1.20 (серверный запуск).

## Очередность после скриншота v0.1.21
1. Диагностическая приёмка: WEB_Physical и WebAppPlatform=web. Значения подтверждены владельцем.
2. Не мигрировать существующий аккаунт в TCP автоматом: ProtectedMaxAccountVault.Upsert заменяет запись по номеру, а сохранённый сеанс протокольно привязан к WEB. Сохранить действующий вход.
3. Проектировать отдельный мобильный слот TCP с явной авторизацией, резервной копией и выбором активного протокола для обычных чатов; не обещать автоматического получения WebAppPlatform=android.
4. Уважать официальное доверенное устройство для бота кодов. Подписанный WebAppData не менять.
5. Разработка следующей версии только после защиты миграции и тестов; на данный момент рабочий релиз v0.1.21. Подробнее docs/protocol/mobile-session-isolation-plan-2026-10-27.md.

## Приоритеты после подтверждённой Android-платформы
1. v0.1.21: мобильный TCP-сеанс и WebAppPlatform=android реально подтверждены. Не повторять смену User-Agent.
2. Для бота кодов подтверждения MAX теперь показывает привязку устройства через SIM и мобильный интернет. Рекомендовать предусмотренный официальным приложением процесс Mobile ID/СМС; не осуществлять обход привязки с настольного клиента.
3. Задержка 1–2 минуты остаётся недиагностированной. При необходимости отдельный инструментальный замер только таймингов и кода ошибки без URL/кодов/телефонов и без доступа к чужим секретам; из снимка нельзя вывести причину.
4. Сохранить рабочую v0.1.21, системный VPN неизменен. Для обычных функций MAX продолжить исследование независимых WEB/TCP-сеансов и пользовательского интерфейса.
