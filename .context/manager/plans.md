# План MAX Desktop после v0.1.6

1. Пользователь обновляется на v0.1.6 и запускает `Добавить аккаунт → Проверить соединение (без номера)`. Результат должен показать успешный `SESSION_INIT` и маршрут либо безопасную категорию ошибки по системному прокси и прямым серверам.
2. Если системный прокси определён и соединение прошло, отдельно протестировать один запрос кода; далее проверить серверные ответы AUTH_REQUEST/AUTH/LOGIN без раскрытия секретов.
3. Если прокси не настроен либо не помог и все прямые узлы возвращают TLS EOF до сертификата, сравнить сетевой путь через основное интернет-подключение и мобильную точку доступа; исследовать фильтрацию, маршрутизацию и региональные сетевые особенности без предположений о неправильном SMS-коде.
4. Если прокси требует авторизацию, поддержать её только при отдельно согласованных безопасных настройках; не передавать системные пароли автоматически и не отключать TLS.
5. После реальной авторизации заняться чатами, сообщениями, вложениями и уведомлениями.
6. Сохранять только последний двоичный GitHub Release; фиксировать проверки CI и обновлять целостность капсулы при каждом существенном этапе.
