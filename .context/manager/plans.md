# MAX Desktop — следующий этап после первого реального LOGIN

1. [Доказано владельцем 26.10.2026] Другой аккаунт с ранее установленным дополнительным паролем прошёл SMS→пароль→успешный LOGIN, главный экран показывает «MAX подключён». Сохранение токена следует из ветки кода SaveAuthenticatedLoginAsync; восстановление после перезапуска ещё не проверено.
2. Первый аккаунт ограничен сервером: для подключения второго устройства нужен пароль на уже авторизованном Android, но установка пароля разрешена только через сутки. Это не ошибка VPN, капчи или SMS, и настройки аккаунта не менять без указания владельца.
3. v0.1.14 успешно опубликована; на скриншоте входа v0.1.13. Следующая пользовательская GUI-приёмка — обновление до v0.1.14, закрытие окна авторизации без закрытия MAX Desktop и сохранение/восстановление успешно авторизованного аккаунта.
4. **Главная разработка** — протокольная интеграция чатов и сообщений. Сначала определить доступные серверные запросы/форматы списка чатов и истории для авторизованного Android/WEB сеанса из допустимых исследований; не делать вывод об опкодах без данных. Затем реализовать загрузку списка, выбор чата, чтение истории, отправку и актуализацию списков. Проверять на Windows Runner без учётных данных, затем реальная приёмка. Вложения, уведомления и несколько аккаунтов — отдельные этапы.
5. Не путать «LOGIN success» и готовность чатов: транспорт GetChatsAsync/GetMessagesAsync пока возвращает пустые списки. Нельзя публиковать реальный токен, коды и содержимое частных чатов в общедоступном GitHub или в логах.
6. Системный VPN не выключать и не перенастраивать; QR/TinyFish исключены. Не дублировать SMS автоматически.
