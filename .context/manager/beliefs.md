# Подтверждённые сведения менеджера MAX Desktop — 26.10.2026

- Публичный репозиторий: `lvlaksim1/max-desktop`, Project Manager v2, архитектура Windows .NET 8/WPF по образцу MailRu Desktop.
- По отзывам владельца интерфейс каркаса работает, но запрос кода MAX на v0.1.2 закончился EOF; в v0.1.3 получена уточнённая ошибка `TLS_HANDSHAKE: соединение закрыто удалённым узлом (EOF)`.
- В v0.1.3 дополнительный доверенный корневой сертификат позволил успешно проверить TLS на GitHub Windows, но **не устранил обрыв в пользовательской сети**. Это подтверждено повторным скриншотом владельца.
- GitHub Windows проба [40246937237](https://github.com/lvlaksim1/max-desktop/actions/runs/40246937237) подтвердила успешный TLS 1.3 при обоих вариантах протокольной настройки: `SslProtocols.None` и явный `Tls12 | Tls13`, при проверке корневого сертификата MAX. Следовательно, отличие TLS-конфигурации **не доказано причиной EOF** на компьютере владельца.
- Публичные DNS, TCP, TLS и анонимный `SESSION_INIT` у GitHub Actions проходят успешно (пробы 40245884044, 40246081737). Проверка именно из пользовательской сети отсутствует.
- В v0.1.4: `NativeMaxTransport` использует системный выбор TLS, проверяет до трёх DNS-адресов с пятсекундной паузой и тем же SNI/валидацией TLS, предоставляет `ProbeConnectionAsync`, который делает только анонимный `SESSION_INIT`. Окно входа содержит кнопку `Проверить соединение (без номера)`.
- Windows CI [40247220377](https://github.com/lvlaksim1/max-desktop/actions/runs/40247220377) успешно прошёл; Release workflow [40247380634](https://github.com/lvlaksim1/max-desktop/actions/runs/40247380634) успешно собрал и опубликовал v0.1.4 с Setup, Update и SHA-256, оставив один последний выпуск.
- **Полноценная авторизация MAX, доставка SMS и получение чатов/сообщений не подтверждены.** Вспомогательная проверка не отправляет телефон, код, пароль, токены.
- Ранее исправленная ошибка обновителя (занятый файл SHA-256) устранена в v0.1.2; клиент 0.1.4 сохраняет эту исправленную реализацию.
