# Подтверждённые сведения менеджера MAX Desktop — 26.10.2026

- Репозиторий `lvlaksim1/max-desktop` публичный, Project Manager v2, архитектура Windows WPF/.NET 8 по образцу MailRu Desktop.
- В версии v0.1.4 пользователь нажал `Проверить соединение (без номера)`. Все три подключения к `api2.oneme.ru` закрылись на `TLS_HANDSHAKE` (EOF) **до получения серверного сертификата**. Поэтому причина не связана с номером, SMS или командой AUTH_REQUEST.
- В GitHub Windows самостоятельный тест [40248116311](https://github.com/lvlaksim1/max-desktop/actions/runs/40248116311) успешно подтвердил TLS 1.3, `SESSION_INIT` (код операции 6) и наличие `callsSeed` на трёх узлах: `api2.oneme.ru`, `api.oneme.ru`, `api-tg.oneme.ru`. Ни в одной из проверок не использовались персональные данные, SMS или учётные токены.
- В v0.1.5 клиент при неудаче защищённого подключения пробует проверенные имена серверов в порядке `api2` → `api` → `api-tg`, затем их дополнительные DNS-адреса. До 2 IP на сервер, 6 попыток суммарно, пауза ≥5 с между попытками. Для каждого TLS всегда передаётся реальное имя домена и проверяется серверный сертификат.
- В окно входа добавлены отмена длительной операции и обезличенные сведения об этапах и исходах подключения к трём серверам. Подтверждено, что при успехе реальной авторизации диалог может закрыться.
- Windows CI [40248715602](https://github.com/lvlaksim1/max-desktop/actions/runs/40248715602) success; Windows Release [40248874326](https://github.com/lvlaksim1/max-desktop/actions/runs/40248874326) success. Опубликован только последний выпуск [v0.1.5](https://github.com/lvlaksim1/max-desktop/releases/tag/v0.1.5), есть Setup, Update и SHA-256.
- **Реальное соединение из пользовательской сети с любым из новых резервных узлов ещё не проверено; серверная SMS-авторизация и переписки не подтверждены.** Не представлять выпуск v0.1.5 как готовый мессенджер.
