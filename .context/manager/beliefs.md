## Пользовательская приёмка v0.1.8 (26.10.2026)
Пользователь показал четыре отказа без номера: TCP — TLS/EOF до сертификата на девяти попытках, .NET WebSocket — WS_CONNECT/TLS EOF, Chromium Edge — WS_CONNECT до открытия соединения, автоматический — отказ первого браузерного варианта. Общий адресный суффикс: *.oneme.ru. Прежняя методическая ошибка — перенос удачных проверок с GitHub Windows (другая сеть) на сеть пользователя и последовательная замена транспортов без независимого теста доступности домена на его компьютере. Возможное единое препятствие — DNS, прокси/VPN, SNI/фильтрация TLS или маршрут; точный фактор не установлен. См. docs/protocol/network-root-cause-2026-10-26.md.

## Подтверждение отказа вне MAX Desktop — 26.10.2026
- В Яндекс Браузере пользователя запрос `https://ws-api.oneme.ru/websocket?utm_source=chatgpt.com` завершается «Соединение было неожиданно прервано»; ответные HTTP-заголовки отсутствуют.
- На том же Windows без utm-параметра `curl.exe -I --max-time 15 https://ws-api.oneme.ru/websocket` возвращает **curl (35), schannel: failed to receive handshake, SSL/TLS connection failed**.
- Общая ошибка **доказанно воспроизводится вне MAX Desktop**, поэтому прежние транспортные перестройки были методически необоснованны. Но конкретный механизм отказа (провайдер/локальная сеть/VPN/фильтр/SNI/сервер) ещё не определён.
- Следующая решающая проверка — **тот же ПК через другой независимый интернет-канал**, повторить curl; не выпускать новое обновление до локализации.
