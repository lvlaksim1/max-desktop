# MAX Desktop — активные обязательства (26.10.2026)

## I-001 — Windows-клиент, установка и обновления
- **active, ожидает пользовательской приёмки:** Windows CI и выпуск v0.1.10 успешны. Проверить обновление установленной v0.1.9 до v0.1.10 без потери данных, поведение главного окна, трея и одного экземпляра.

## I-002 — вход обычного аккаунта MAX без QR
- **active.** Рабочее подключение через физический сетевой интерфейс подтверждено на ПК владельца: HTTPS/TLS, WebSocket 101 и SESSION_INIT в установленной v0.1.9.
- При реальном START_AUTH(17) сервер ответил «Проверка не пройдена, попробуйте ещё раз». Наиболее вероятно отсутствие подтверждённой проверки человека; точный error code не получен.
- В v0.1.10 добавлено ручное получение CAPTCHA_REQUEST(224), окно VK ID и передача выданного пользователю captchaToken. Проверены сборка и автономный цикл; **реальное решение капчи и доставка кода ещё не приняты**.
- Следующие критерии: окно капчи отображается/человек проходит её → сервер принимает START_AUTH ровно один раз после проверки → SMS или альтернативное серверное подтверждение → код → 2FA при необходимости → LOGIN и восстановление сеанса.
- QR строго исключён, повторные SMS при неопределённом ответе запрещены.

## I-003 — чаты, сообщения, вложения и уведомления
- **active, зависит от I-002.** Незавершённые модули не выдавать за рабочие.

## I-004 — жизненный цикл Windows-окна
- **active до пользовательской приёмки:** X→трей, «−»→панель задач, правый клик по трею→«Выход», повторный запуск без нового экземпляра, корректное закрытие перед обновлением.

## I-005 — работа при неизменном системном VPN
- **реализовано и подтверждено до INIT.** Владелец разрешает MAX любой маршрут, но настройки VPN менять нельзя. Физический интерфейс обеспечивает подключение без изменений Windows/VPN; в v0.1.10 он сохранён.
- Для локальных проверок использовать только приватный pc-runner-gateway, точные SHA коммитов; TinyFish не применять.
