# MAX Desktop — активные обязательства

## I-001 — Windows-клиент, установка и обновления
- **active (GUI-приёмка)**: реализация/CI и релиз v0.1.8 подтверждены. Проверить на компьютере владельца обновление, сохранение данных и четыре сценария окна/трея; не путать успешно собранный код с пользовательской приёмкой.

## I-002 — вход обычного аккаунта MAX без QR
- **active, блокирующая зависимость — независимый TLS-отказ.** Реализованы TCP, WEB .NET и WEB Chromium/WebView2, но пользовательские попытки обрываются до INIT/SMS. Отладку авторизации продолжить только после установления работающего подключения или достоверной локализации сетевого отказа.
- Нужны реальная выдача SMS, подтверждение кода, 2FA при необходимости, сохранение/восстановление токена и подтверждённый LOGIN. **Ничего из этого на аккаунте пользователя не принято.**

## I-003 — чаты, сообщения, вложения и уведомления
- **active, зависит от I-002**; заглушки не представлять работающей функциональностью.

## I-004 — требования к жизненному циклу Windows-окна
- **active до пользовательской приёмки**: X→трей, «−»→панель задач, правое меню трея «Выход», второй запуск активирует имеющийся экземпляр; при обновлении процесс полностью завершается.

## I-005 — локализовать TLS-отказ вне приложения
- **active; самый высокий приоритет.** Браузер и системный curl на том же ПК уже продемонстрировали сбой. Продолжить локализацию через разрешённый PC Runner Gateway **при включённом VPN**. Проверки №394–398 локализовали TLS-отказ после успешного HTTP CONNECT через локальный Xray/TUN. Проверить маршрутизацию/выход VPN, не менять сеть и настройки без согласования. Не выпускать новую версию только ради очередной замены транспорта.
