# MAX Desktop — активные обязательства (26.10.2026, v0.1.11)

## I-001 — Windows-клиент и автообновления
- **active; приёмка на ПК владельца**: опубликован v0.1.11 (полный и обновляющий установщики + SHA-256), Windows CI и release workflow завершены успешно. Подтвердить обновление поверх прежней установки и сохранение сеансов.

## I-002 — реальная авторизация MAX по телефону, без QR
- **active**: на пользовательском ПК с включённым VPN подтверждён SESSION_INIT через физический интерфейс. В v0.1.9 START_AUTH(17) дал отказ «Проверка не пройдена».
- В v0.1.10 пользователь видел VK Captcha и установил галочку, но приложение не распознало завершение. v0.1.11 заменяет самодельный перехват сообщений на официальное событие SDK SUCCESS({token}); сборка и автономный тест успешны.
- **Следующая проверка:** установить v0.1.11, запросить код один раз и вручную пройти проверку. При успешном callback — один START_AUTH с captchaToken, затем SMS/код/2FA при необходимости/LOGIN/сохранение сеанса. Реальное завершение не доказано.
- Не решать капчу автоматически и не повторять SMS при неопределённом результате.

## I-003 — чаты, сообщения, вложения и уведомления
- **active, зависит от I-002**. До настоящего входа не выдавать за работающую функциональность.

## I-004 — поведение Windows-приложения
- **active до приёмки**: X→трей, «−»→панель задач, контекстное меню трея «Выход», повторный запуск без копии, правильное завершение при обновлении.

## I-005 — обязательное сосуществование с системным VPN
- **работоспособность до SESSION_INIT подтверждена**: VPN всегда включён, менять его настройки нельзя; приложение выбирает физический IPv4 только для собственных соединений MAX, не меняет системные маршруты.
- Через ПК-владельца запускать read-only проверки только посредством приватного pc-runner-gateway, не использовать TinyFish.
