## I-001 — Windows-клиент и обновления
- **active; пользовательская приёмка:** v0.1.13 опубликован с Setup/Update/SHA256; Windows CI #40345636022 и релиз #40346233767 успешны. Проверить обновление поверх v0.1.12 и сохранность настроек и сеансов.

## I-002 — настоящая авторизация пользователя, без QR
- **active:** веб-подключение через физический интерфейс, VK Captcha и доставка SMS подтверждены. WEB CHECK_CODE(18) возвращает серверное требование установить 2FA; ошибку протокола от ошибки сервера теперь можно отличить.
- [Владелец] Официальное приложение **Android** авторизуется без капчи и требования 2FA. Тип клиентского протокола отличается от WEB; состояние доверенного Android-устройства не установлено.
- [v0.1.13] Добавлен отдельный Android TCP (v10) через физический IPv4 без изменения VPN. Вход вручную не переводится из WEB после SMS. На ПК TLS подтверждён (#404), на GitHub Windows Runner новый C# транспорт подтвердил анонимный INIT (#40345635857).
- **Следующий критерий:** в установленной v0.1.13 выбрать «TCP Android через физический интерфейс», проверить соединение **без номера**, затем только при успешном INIT выполнить отдельную пользовательскую попытку авторизации. Сервер может всё равно потребовать дополнительную проверку; реальный LOGIN пока не принят.
- Запрещены QR, автоматическое дублирование SMS и несогласованное изменение VPN.

## I-005 — работа при неизменном системном VPN
- **частично завершено до TLS/INIT:** физический WebSocket подтверждён пользователем до INIT; мобильный TCP/TLS также проходит на его ПК, а INIT в новой реализации проверен на облачном Windows. VPN постоянно включён и не изменяется. Локальные проверки через приватный pc-runner-gateway, без TinyFish.
