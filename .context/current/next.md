# MAX Desktop — первые шаги в новом чате (v0.1.10)

1. Восстановить существующего менеджера из `.context/ENTRYPOINT.md` и проверить `.context/manager/state-integrity.json`.
2. Знать, что TLS/WebSocket/SESSION_INIT через физический интерфейс **уже подтверждены на ПК владельца скриншотом v0.1.9**. VPN всегда включён, настройки менять нельзя. Трафик MAX разрешён через любой маршрут без изменения VPN.
3. На том же снимке ошибка START_AUTH(17): `WS_AUTH_REQUEST: Проверка не пройдена, попробуйте ещё раз`. Вероятная CAPTCHA, не TLS.
4. В GitHub опубликован v0.1.10 с ручной VK Captcha (224 → окно WebView2 → captchaToken → SMS), успешная сборка и офлайн тест. Следующее действие: пользовательская приёмка установленной v0.1.10, один запрос кода и выполнение задания человеком.
5. Если CAPTCHA не открывается/не завершается, разобраться по обезличенному сообщению; токен, SMS и номер не просить. Не выпускать непроверенных обходов и не повторять SMS автоматически.
6. После принятого кода: VerifyCode → 2FA при необходимости → LOGIN → восстановление сессии; затем сообщения/чаты, окно/трей, обновитель.
7. Для локальных автоматизированных испытаний использовать `lvlaksim1/pc-runner-gateway` (приватная очередь GitHub Issues + неизменный SHA); TinyFish не использовать, системный VPN не трогать.
