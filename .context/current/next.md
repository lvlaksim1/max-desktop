# MAX Desktop — следующий технический этап

1. Скриншот v0.1.21 подтвердил WebSocket/WEB/physical и WebAppPlatform=web. Дополнительная диагностика User-Agent здесь не нужна.
2. До попытки мобильной авторизации для уже добавленного номера подготовить независимое DPAPI-хранение сеансов WEB и TCP, резервное копирование старого файла и регрессионные испытания миграции. Текущий ProtectedMaxAccountVault.Upsert перезаписывает по Phone.
3. Добавить явно выбранное подключение TCP(Android) для общей клиентской функциональности, сохранив рабочий WEB и не требуя от пользователя немедленного повторного входа.
4. Проверить после добровольной мобильной авторизации серверный BOT_WEB_APP(160), платформу и обычные функции; не подменять WebAppData, DeviceId и доверенное устройство для получения защищённых кодов.
5. Соблюдать ранее заданные ограничения: VPN неизменен, QR/TinyFish/отправка сообщений не нужны. См. docs/protocol/mobile-session-isolation-plan-2026-10-27.md.
