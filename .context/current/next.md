# MAX Desktop — первые действия в новом чате

1. Восстановить менеджера `project-manager` из `.context/ENTRYPOINT.md`, проверить поколение и все дайджесты `.context/manager/state-integrity.json`.
2. **Инвариант владельца: системный VPN включён постоянно; отключать нельзя.** Не повторять устаревший совет «отключить VPN/перейти на мобильную сеть».
3. Для удалённого выполнения на компьютере использовать **только** `lvlaksim1/pc-runner-gateway`. Читать `.pc-gateway/ENTRYPOINT.md`, формировать приватный Issue, закреплять полный SHA коммита и путь разрешённого скрипта; не использовать TinyFish.
4. Наблюдаемые факты в запросах шлюза №394–398: DNS и TCP 443 доступны, локальный HTTP-прокси процесса Xray + TUN; CONNECT 200 до MAX, но TLS отказывает с curl 35 при 1.2/1.3; GitHub через тот же прокси HTTP 200.
5. Определить безопасный способ маршрутизации адресов MAX при продолжающем работать VPN. Прежде чем менять VPN/прокси/DNS/маршруты — согласовать конкретные изменения с владельцем. Корневая причина ещё не доказана.
6. При рабочем TLS на том же ПК проверить INIT → один запрос SMS → код → 2FA при необходимости → LOGIN. До этого не выпускать случайную v0.1.9.
7. Затем перейти к чатам и окончательной проверке функций Windows-окна, трея и обновлений.
