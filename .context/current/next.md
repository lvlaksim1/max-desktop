# MAX Desktop — первые действия следующего чата

1. Восстановить того же `project-manager`, проверить `.context/manager/state-integrity.json` по восьми Git blob SHA.
2. Последний выпуск **v0.1.13**, Setup/Update/SHA256 и только один релиз в https://github.com/lvlaksim1/max-desktop/releases/tag/v0.1.13 . GitHub CI #40345636022 и release #40346233767 прошли.
3. Владелец уточнил: официальный клиент, входящий без капчи/2FA, — **Android**, не Windows. WEB-протокол MAX Desktop v11 возвращает требование 2FA после SMS, а мобильный TCP v10 реализован на основе APK 26.35.1. Реальное отличие ограничений для новой сессии не доказано.
4. На компьютере с работающим системным VPN через pc-runner-gateway #404 проверены TLS всех трёх мобильных узлов через физическую сетевую карту. На GitHub Windows Runner #40345635857 новый физический TCP подтвердил SESSION_INIT. **На самом ПК в установленной версии INIT ещё не проверен**.
5. Следующий пользовательский шаг: установить v0.1.13, вручную выбрать «TCP Android через физический интерфейс (VPN включён)» и нажать «Проверить соединение (без номера)». Если успешен INIT — затем один отдельный запрос SMS/код и фактический LOGIN. Не повторять код и не публиковать данные.
6. Если сервер и на мобильном протоколе требует 2FA, фиксировать ответ как политику сервера и не обходить серверную защиту. После успешного LOGIN перейти к чатам, сообщениям и GUI.
7. VPN не отключать и не менять. Только pc-runner-gateway для ПК и GitHub Actions для CI; без TinyFish и QR.
