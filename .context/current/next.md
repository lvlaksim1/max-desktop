# MAX Desktop — приоритетное продолжение с 28.10.2026
1. Работать автономно по прямому указанию владельца: использовать исходники, существующие автоматические проверки, подключённый PC Gateway и исследования, не требуя согласований на обычные шаги. Учитывать техническую изоляцию рабочего стола PC Gateway.
2. Следующий недостающий факт: где именно в реальном мини-приложении MAX формируется запрос Mobile ID и как сервер предлагает штатное подтверждение. Измерять лишь структурные счётчики кадров и факты обращений, без URL, DOM, содержимого сообщений, токенов, SMS и значений кодов.
3. Сопоставлять данные со схемой Android 26.35.1 (по решению владельца эквивалентность нужного механизма с 26.36.2 — рабочая гипотеза); не сбрасывать работающее доверие телефона и не повторять сетевые/USB тесты без причины.
4. Если нет возможности получить реальное наблюдение с доступной инфраструктурой, зафиксировать технический блокер и разработать следующий проверяемый безопасный путь; не объявлять очередную версию исправлением кодов без приёмки.
5. Сохранять цель: реальный защищённый код после принятого сервером подтверждения в окне MAX Desktop. Исходный обзор: docs/protocol/webview2-frame-routing-2026-10-27.md; текущая установленная v0.1.23 не содержит новую маршрутизацию iframe.
