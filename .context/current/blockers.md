# MAX Desktop — блокирующие условия

1. **Подтверждённый TLS-сбой вне приложения.** На Windows пользователя `ws-api.oneme.ru` не открывается даже в Яндекс Браузере и системном `curl.exe` (ошибка 35/Schannel). Все четыре режима MAX Desktop также не доходят до INIT.
2. **Неустановленная конкретная причина.** Варианты: исходный интернет-маршрут, провайдер/фильтрация по SNI, DNS, VPN/прокси, антивирус/сетевой экран, Windows, серверная доступность. Доказательств выбора одной причины пока нет.
3. **Ожидаемая проверка:** тот же компьютер через мобильную точку доступа/другую независимую сеть и тот же `curl.exe` без SMS. Приёмка реальной авторизации заблокирована до рабочего соединения.
4. Не подтверждены фактическая доставка SMS, 2FA, LOGIN, переписки, а также пользовательский результат X→трей/«−»→панель задач/одного экземпляра.
5. QR исключён прямым указанием владельца. Секреты не записывать в общедоступные файлы. Не отключать проверку сертификатов ради получения «успешного» соединения.

6. [Владелец] Системный VPN всегда включён, отключение запрещено. Возможная адресная маршрутизация MAX должна сохранять работу VPN и согласовываться с владельцем.
7. [Локальный шлюз, запросы №394–398] TCP и DNS MAX доступны; HTTP CONNECT через локальный Xray-прокси даёт 200; TLS и 1.2, и 1.3 обрывается до HTTP. Обычные сайты через тот же прокси работают. Не доказано, блокирует ли VPN-выход, сервер или другая фильтрация.
8. До успешного HTTPS на пользовательском ПК блокирована реальная авторизация. Повторение тестов внешнего GitHub Runner не заменяет локальную диагностику.
