# MAX Desktop — текущее состояние на 26.10.2026

- Репозиторий: `lvlaksim1/max-desktop`, ветка `main`, менеджер `project-manager`, Context Capsule v2.
- **Последний опубликованный релиз v0.1.8**: https://github.com/lvlaksim1/max-desktop/releases/tag/v0.1.8. Setup, Update и SHA-256 подтверждены; выпуск/CI Actions 40255959472 (success), 40255959364 (success). Нового установщика после v0.1.8 нет.
- Реализованы WEB/WebSocket JSON v11 по номеру/SMS через .NET и Chromium/WebView2, опытный TCP/TLS, DPAPI-сеансы и механизм обновления. QR исключён по решению владельца.
- Владелец проверил v0.1.8: TCP, .NET WebSocket, Chromium и автоматический режим **не могут установить защищённое соединение**. До команды запроса SMS дело не доходит.
- **Решающая независимая проверка завершена:** Яндекс Браузер без HTTP-ответа прервал соединение к `ws-api.oneme.ru`; PowerShell `curl.exe -I --max-time 15 https://ws-api.oneme.ru/websocket` на том же ПК вернул `curl: (35) schannel: failed to receive handshake, SSL/TLS connection failed`. Сбой воспроизводится вне нашего приложения.
- **Сопоставимый тест Windows Runner 26.10.2026:** HEAD к https://ws-api.oneme.ru/websocket через curl.exe — код 0, HTTP 403 (Actions 40315701059); на ПК владельца ранее curl 35. Анонимные проверки .NET/Chromium/TCP также успешны на Runner. Это подтверждает различие сред, но не конкретную причину отказа.
- Точная локальная причина не установлена; внешний успех GitHub Windows не переносится на сеть пользователя. **Следующий опыт — тот же ПК через другую независимую сеть**, а не новые версии протокола.
- Реальная доставка SMS, вход, 2FA, чаты/сообщения и пользовательская приёмка трея/окна **не подтверждены**.
- Подробный отчёт: `docs/protocol/network-root-cause-2026-10-26.md`.

- **Постоянный VPN — обязательное условие владельца:** запрещено требовать его отключения; MAX Desktop должен работать с VPN включённым.
- **Локальный Windows Runner подключён через частный шлюз** `lvlaksim1/pc-runner-gateway`; MAX Desktop разрешён как клиент, установлен официальный комплект `.pc-gateway/`. Запросы 392–398 завершились успешно.
- **Локальная диагностика:** 2 IPv4-адреса ws-api.oneme.ru, TCP 443 доступен, системный HTTP-прокси на loopback управляется Xray, присутствует TUN-интерфейс. HTTP CONNECT до адресов MAX = 200, но затем TLS 1.2/1.3 обрывается (curl 35), одинаково для ws-api.oneme.ru и web.max.ru. Через тот же прокси GitHub = CONNECT 200/HTTP 200. Точная причина отказа после CONNECT ещё не доказана.
- **Следующая задача:** изучить правила/выход маршрутизации Xray без выключения VPN. Конфигурацию VPN не изменять без согласования. Выпуск v0.1.8 не менялся.
