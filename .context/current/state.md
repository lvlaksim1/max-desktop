# MAX Desktop — состояние после пользовательского скриншота 27.10.2026

- Репозиторий lvlaksim1/max-desktop, main, manager project-manager. Последний релиз v0.1.21. Диагностические данные пользовательски проверены: активный сеанс WEB_PHYSICAL («WebSocket / WEB / физическая сеть»), WebAppPlatform в server-signed URL = web.
- Кнопка «Посмотреть код» запускает настоящий подписанный miniapp через BOT_WEB_APP(160), но сервис требует мобильную версию. Нет свидетельств, что простой User-Agent снимет отказ. Официальная проверка доверенного устройства — самостоятельное условие MAX.
- Исходники: NativeMaxTransport поддерживает TCP Android; HybridMaxTransport при Automatic использует WEB_PHYSICAL, восстановление использует сохранённый Transport. ProtectedMaxAccountVault.Upsert хранит ровно один сеанс на номер телефона и заменяет существующий при повторном входе. Нельзя без отдельной изоляции сделать новую мобильную авторизацию для того же номера, не рискуя WEB-сеансом.
- Следующий архитектурный этап: параллельные, изолированные WEB/TCP слоты и явный выбор протокола для обычных чатов, не затрагивая существующие аккаунты, VPN, подписанные WebAppData и проверку доверенного устройства. Исследование: docs/protocol/mobile-session-isolation-plan-2026-10-27.md.
- В этом этапе внесены только исследовательские материалы, без новой версии и изменений рабочего сетевого кода.
