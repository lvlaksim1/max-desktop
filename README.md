# MAX Desktop

Нативный клиент MAX для Windows 10/11 на C# / .NET 8 / WPF.

## Реализовано в версии 0.1.1 (опытная авторизация)

- Главное трёхпанельное окно (аккаунты, чаты, переписка), изменяемые разделители.
- Темы оформления, восемь основных цветов, сохранение размеров и положения окон.
- Одно запущенное приложение, значок в области уведомлений, отдельные настройки.
- Нативная авторизация MAX через TCP/TLS: запрос кода, проверка кода, дополнительный пароль, команда входа, защищённое сохранение сеанса. Проверка работоспособности на реальном аккаунте ещё не завершена.
- Проверка новых GitHub Releases, загрузка обновления с проверкой SHA-256 и отдельный агент установки.
- Полный и обновляющий установщики Inno Setup без прав администратора.
- Автоматизированная Windows-сборка, проверка протокольной границы, выпуск установщиков и политика хранения.

**Авторизация подключена программно, но ещё не проверена на настоящем аккаунте MAX.** Загрузка чатов и обмен сообщениями не реализованы. Вход может быть отклонён, если MAX изменил внутренний протокол или требует альтернативного подтверждения. [Спецификация и порядок приёмки](docs/protocol/authorization-26.35.1.md); исследование APK — в [max-android-research](https://github.com/lvlaksim1/max-android-research).

## Код и сборка

- `src/MaxDesktop.App` — нативное WPF-приложение.
- `src/MaxDesktop.Protocol` — интерфейсы и изолированный транспорт.
- `src/MaxDesktop.UpdateAgent` — запуск установщика после закрытия программы.
- `installer/full.iss`, `installer/update.iss` — сценарии Inno Setup.
- `tests/MaxDesktop.Protocol.Smoke` — проверки MessagePack, LZ4, формата TCP-кадров, отпечатка сеанса и границ авторизации.
- [Архитектура](docs/architecture-baseline.md) · [Примечания по реализации](docs/implementation-notes.md).

Сборка Windows: `dotnet build src/MaxDesktop.App/MaxDesktop.App.csproj -c Release`. Для первой установки применяется `MaxDesktop_Setup_vX.Y.Z.exe`, для обновления — `MaxDesktop_Update_vX.Y.Z.exe`. Готовые выпуски доступны в [GitHub Releases](https://github.com/lvlaksim1/max-desktop/releases) после успешной проверки.

Двоичные сборки не сохраняются в истории Git или в артефактах GitHub Actions. Установлен профиль Project Manager v2 через [Repo Factory](https://github.com/lvlaksim1/repo-factory).

## Исследование TLS и входа (v0.1.3)

После отчёта пользователя об обрыве соединения при запросе кода в v0.1.2 проведены безопасные сетевые проверки без телефона и учётных данных. На Windows обнаружена ошибка стандартной цепочки TLS, подтверждено успешное подключение через дополнительный доверенный центр сертификации MAX и успешный `SESSION_INIT`. Подробности и границы проверки: [диагностика TLS](docs/protocol/tls-auth-diagnostics-2026-10-26.md). Реальное получение кода пока не подтверждено.

## v0.1.4: диагностика обрыва TLS

После пользовательского сообщения `TLS_HANDSHAKE / EOF` выяснено, что оба варианта выбора TLS работают в GitHub Windows, а в пользовательской сети обрыв повторяется. Добавлена кнопка проверки соединения без номера телефона и безопасная смена DNS-узла (до трёх, пауза 5 секунд). TLS остаётся обязательным, имя сервера и цепочка сертификата проверяются. [Технический отчёт](docs/protocol/tls-auth-diagnostics-2026-10-26.md). Реальное получение кода пока не принято.

## Сетевая устойчивость v0.1.5

В пользовательской сети `TLS_HANDSHAKE` завершается EOF ещё до получения сертификата даже после трёх попыток на IP-адресах `api2.oneme.ru`. Проверка [GitHub Actions 40248116311](https://github.com/lvlaksim1/max-desktop/actions/runs/40248116311) подтвердила успешные TLS 1.3 и `SESSION_INIT` для трёх продакшен-узлов: `api2.oneme.ru`, `api.oneme.ru`, `api-tg.oneme.ru`.

В новой версии клиент поочерёдно пробует разные домены (не более 6 адресов суммарно), с паузой не менее 5 секунд и строгой проверкой сертификата относительно текущего домена. В окно входа добавлена отмена длительной проверки. Для анализа используется кнопка **«Проверить соединение (без номера)»**. Подробности: [диагностика](docs/protocol/tls-auth-diagnostics-2026-10-26.md). Успешная авторизация в сети пользователя пока не доказана.
