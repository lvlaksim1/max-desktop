# MAX Desktop — исходная архитектура

Статус: согласование исходных требований. Архитектурный образец: [MailRu Desktop](https://github.com/lvlaksim1/mailru-desktop). Предметная область и сетевой протокол приложения MAX разрабатываются отдельно.

## Назначение

Самостоятельный нативный Windows-клиент мессенджера MAX, построенный по организационным и техническим принципам MailRu Desktop. Не копировать почтовую логику, API Mail.ru, почтовые формы и структуру данных писем.

## Технологии и разделение ответственности

- C# / .NET 8, WPF, Windows 10/11.
- `src/MaxDesktop.App`: оформление окон, взаимодействие с пользователем, список чатов и переписка, настройки, значок области уведомлений.
- `src/MaxDesktop.Protocol`: отдельная библиотека транспортного обмена и авторизации MAX, не зависящая от WPF.
- `src/MaxDesktop.UpdateAgent`: самостоятельный механизм запуска обновления поверх установленной версии.
- `tests/`: проверка состояния интерфейса, процедур обновления и протокола без зависимости от окон.
- `docs/protocol/`: исследовательские материалы с указанием источников и уровня подтверждения.

Источник для изучения протокола: [max-android-research](https://github.com/lvlaksim1/max-android-research). Учитывать, что результаты анализа APK 26.35.1 являются **статическими**; совместимый с сервером сетевой обмен и независимый вход ещё не подтверждены. Не выдавать предположения за работающие функции.

## Первая установка — отдельный полный установщик

- Inno Setup: `installer/full.iss`.
- Имя: `MaxDesktop_Setup_vX.Y.Z.exe`.
- Установка в профиль текущего пользователя без прав администратора.
- Каталог файлов: `%LOCALAPPDATA%\Programs\MaxDesktop`.
- Создание ярлыка меню «Пуск»; ярлык рабочего стола по желанию пользователя.
- Данные, настройки, состояние интерфейса и защищённые учётные сведения хранятся вне каталога установки, в `%LOCALAPPDATA%\MaxDesktop`.
- Удаление приложения через штатный деинсталлятор с очисткой данных, принадлежащих приложению, по образцу MailRu Desktop.

## Обновления — самостоятельный установщик поверх текущего приложения

- Inno Setup: `installer/update.iss`.
- Имя: `MaxDesktop_Update_vX.Y.Z.exe`.
- Установщик обновления не используется для первой установки и не удаляет существующие пользовательские данные.
- Кнопка обновления в приложении проверяет последний GitHub Release, получает соответствующий файл и запускает обновление без лишних диалогов. Показывать ход операции.
- Сохранить настройки, аккаунты, локальное состояние, положение окон, значки и ярлыки.
- После обновления приложение запускается в новой версии; при удалении приложения очищаются только собственные каталоги и настройки.

## Интерфейс — те же принципы, предметные элементы другие

Перенять из MailRu Desktop: собственные нативные окна; светлую, тёмную и системную темы; выбор основных цветов; компактное расположение элементов; изменяемые панели и разделители; сохранение размеров, положения окон и настроек столбцов; отдельное окно настроек; значок в области уведомлений; работу одного экземпляра; уведомления с переходом к нужной переписке; отображение версии в заголовке.

Предварительная компоновка MAX: список аккаунтов и чатов слева, выбранная переписка и история сообщений справа, поле ввода и вложения внизу. Сообщения, групповые беседы, вложения, пересылка, поиск и другие возможности должны зависеть от проверенных возможностей протокола. Детальную компоновку и состав функций уточнять при реализации.

## Сборка и публикация

- GitHub Actions: сборка/проверки кода и подготовка установщиков.
- Исполняемые файлы Setup/Update публиковать только как файлы GitHub Releases, не как GitHub Actions artifacts и не в историю Git.
- Оставлять последний двоичный выпуск; придерживаться действующей политики Repo Factory (в том числе запрета отслеживаемых исполняемых файлов и лимита 5 МиБ).
- Версию приложения, установщика и GitHub Release поддерживать согласованной.
- Новые решения и принятые изменения сохранять в репозитории и Project Manager.

## Границы этапа создания репозитория

На начальном этапе зафиксировать архитектуру и установить менеджер проекта. Наличие документа **не означает**, что уже собран исполняемый клиент, установщик, обновитель либо реализована авторизация. Для каждого из них необходима отдельная реализация и приёмка.
