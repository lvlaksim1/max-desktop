# MAX Desktop v0.1.21 — проверка платформы и протокола

- В карточке подключённого аккаунта теперь явно указан фактически используемый транспорт: TCP/Android или WebSocket/WEB, с уточнением сетевого маршрута.
- В окне мини-приложения отображается только несекретное значение `WebAppPlatform`, пришедшее в подписанном URL запуска MAX: `android`, `ios`, `web`, `desktop` или отсутствие определённого значения.
- Платформа, подписанные `WebAppData` и идентификатор устройства не изменяются. User-Agent не подделывается. URL с данными входа не выводится и не записывается в журнал.
- Добавлены автономные тесты определения платформы по URL без раскрытия данных авторизации.
- Сохранены запрос `BOT_WEB_APP (160)`, уже работающий HTTPS-маршрут мини-приложений, сеансы нескольких аккаунтов и их защищённое хранение.

**Причина отдельной диагностики:** TCP-протокол называет устройство Android, а встроенный WebView2 остаётся средой Windows. Одно не делает другое доверенным мобильным устройством. Бот «Коды подтверждения» в v0.1.20 явно ограничивает просмотр кодов мобильным приложением. В v0.1.21 это ограничение не обходится; штатная проверка доверенного устройства через MAX сохраняется.

**Приёмка:** посмотреть строку «Протокол» под активным аккаунтом и строку «Платформа запуска в URL» после нажатия «Посмотреть код». По их значениям определить, в каком слое проявляется несоответствие. Отправка обычных сообщений отключена, системный VPN не изменяется.
