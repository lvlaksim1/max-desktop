# MAX Desktop v0.1.20 — полноценный серверный запрос запуска мини-приложений

- Реализован штатный запрос `BOT_WEB_APP` (код 160) из уже авторизованного сеанса MAX: `botId`, `chatId`, необязательный `startParam`.
- Поддержаны оба сетевых протокола: TCP/MessagePack и WebSocket/JSON, включая физический маршрут при включённом системном VPN.
- Кнопки `OPEN_APP` в сообщениях теперь запрашивают у сервера MAX подписанный адрес мини-приложения, а не открывают публичную страницу бота.
- Полученный URL используется только в памяти и только для открытия отдельного окна WebView2. Подписанный адрес никогда не публикуется в диагностике, журналах или ошибках; возможность открытия во внешнем браузере удалена.
- При смене чата/учётной записи ожидающий запуск отменяется. Отдельный браузерный профиль и ограничение разрешений сохранены.
- Добавлены проверки запроса, разбора ответа, сохранности подписанных параметров, запрета опасных адресов, отсутствия вымышленной ссылки при отказе сервера.
- Исправленный в v0.1.19 сетевой маршрут мини-приложений, несколько аккаунтов и история переписок сохранены.

**Граница проверки:** запрос и построение проходят автоматические испытания. Реальная работа кнопки «Посмотреть код» в `@verificationcodes_bot` ещё не принята пользователем. Сервис может запросить штатную проверку доверенного устройства; обходить её клиент не будет. Функции мини-приложения, требующие дополнительных возможностей MAX Bridge, будут оценены после реальной приёмки. Отправка обычных сообщений остаётся отключённой, системный VPN не меняется.
