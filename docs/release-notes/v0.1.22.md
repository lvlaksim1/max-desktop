# MAX Desktop v0.1.22 — экспериментальная обработка Mobile ID без сотовой сети

## Изменено

- В окне мини-приложений появился ограниченный обработчик исходных событий MAX `WebViewHandler` и `PrivateWebViewHandler`, названия и сигнатуры которых проверены по исходному APK 26.35.1.
- Если мини-приложение отправляет `WebAppVerifyMobileId`, настольный клиент не оставляет запрос без ответа: возвращает точный штатный отрицательный код `client.verify_mobile_id.no_cellular`. Это не запрос СМС и не подтверждение доверенного устройства.
- Формат ответа `requestId/error.code` восстановлен по сериализаторам оригинального APK. Мини-приложение может предложить другой вариант привязки, **только если такой вариант действительно разрешён сервером MAX и настроена 2FA**.
- Обмен ограничен исходным HTTPS-сайтом мини-приложения, полученным в подписанном MAX адресе. Ни один URL, номер телефона, пароль, код, заголовок или содержимое Mobile ID не сохраняется.
- Добавлены автономные проверки формата отрицательного ответа и проверки входных идентификаторов.

## Проверка у пользователя

1. Для тестового аккаунта заранее включите **пароль для входа MAX (2FA)** в официальном мобильном приложении. Статус 2FA должен быть активным на сервере.
2. Откройте в MAX Desktop бот «Коды подтверждения», нажмите «Посмотреть код» → «Привязать новое устройство».
3. Если мини-приложение запрашивает Mobile ID, приложение вернёт `no_cellular` вместо молчания. Проверьте, появился ли штатный выбор подтверждения через СМС.
4. Отсутствие СМС означает, что одного этого обработчика недостаточно; изменение не заявлено как подтверждённое получение кодов.

**Важно:** при входе в MAX Desktop СМС и дополнительный пароль уже работали. СМС для смены доверенного устройства — другой серверный процесс. Новый релиз не имитирует SIM и не изменяет действующие аккаунты или настройки VPN.
