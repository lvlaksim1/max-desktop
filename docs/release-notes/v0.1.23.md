# MAX Desktop v0.1.23 — номер аккаунта и проверяемое состояние Mobile ID

## Исправлено

- В окне мини-приложения отображается **номер текущего авторизованного аккаунта** из сохранённого сеанса MAX. Новый запрос номера, повторный вход и изменение авторизационных данных не нужны.
- Устранён пропуск события в `WebViewHandler.postEvent`: в v0.1.22 он был пустым, хотя официальная библиотека MAX использует этот интерфейс. Теперь узкий, безопасный обработчик `WebAppVerifyMobileId` принимает запрос из `WebViewHandler` и `PrivateWebViewHandler`.
- Добавлено отображение этапов: подключился ли мост, поступил ли запрос Mobile ID, удалось ли передать штатный ответ `client.verify_mobile_id.no_cellular` обратно мини-приложению.
- Сам отрицательный ответ соответствует оригинальному APK при отсутствии сотовой сети. Он не подтверждает устройство и не создаёт СМС-запрос.

## Что не изменено

- Номер аккаунта **не записывается в запрос Mobile ID**, поскольку в оригинальном MAX `WebAppVerifyMobileIdRequest` содержит только `requestId` и `url`. Выдуманный параметр номера не даст операторского подтверждения.
- Серверный механизм смены доверенного устройства и существующие настройки Windows/VPN не меняются.
- Настоящая форма подтверждения через СМС остаётся возможностью только со стороны MAX и может зависеть от включённой 2FA. Её появление на компьютере пока **не подтверждено**.

## Приёмка

1. Установить обновление поверх существующего MAX Desktop.
2. Открыть «Коды подтверждения» → «Посмотреть код». Вверху окна проверить номер аккаунта.
3. Зафиксировать строку о состоянии MAX Bridge под номером. Она не содержит номера SIM, токенов, ссылок, кодов или других секретов.
4. При появлении настоящей формы СМС подтвердить доступ по штатной процедуре. Если форма не появилась — отсутствие перехода остаётся установленным ограничением, а состояние моста поможет отделить ошибку клиента от решения сервера.

Проверки: Windows сборка и автономные протокольные тесты. Защищённые коды не читаются обходными методами.
