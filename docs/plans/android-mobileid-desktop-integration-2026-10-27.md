# MAX Desktop — согласованный план: Android с исследовательской SIM как компонент Windows
Дата: 27.10.2026. Источник: предложение технического плана, одобренное владельцем с прямой просьбой сохранить в капсуле контекста. Статус: **план согласован, этапы не выполнены**.

## Цель и критерий приёмки
Для собственных тестовых аккаунтов: авторизация в MAX Desktop (Windows) → бот «Коды подтверждения» → «Посмотреть код» → подлинный код виден непосредственно в окне MAX Desktop после принятой сервером MAX проверки. Допускается дополнительный физический Android с исследовательской SIM как компонент системы. Сборка установщика, открытие мини-приложения и подтверждение работоспособности местного моста сами по себе не удовлетворяют критерию.

## Подтверждённое состояние
- APK Android MAX 26.35.1 (6867): WebAppVerifyMobileId(requestId,url) → Android TRANSPORT_CELLULAR/INTERNET → HTTP-проверка по сотовой сети → ответ мини-приложению (код, заголовки и данные). Это статически подтверждённая клиентская схема; **условия принятия сервером доверия неизвестны**.
- Источники: lvlaksim1/max-android-research/docs/mobileid-bridge-trace-26.35.1.md, docs/telephony-api-audit-26.35.1.md; локально docs/protocol/verified-apk-sim-mobileid-audit-2026-10-27.md.
- v0.1.23 пользовательски **не принята** для просмотра кодов: экран автоматической проверки номера, отсутствует настоящий код; строка «MAX Bridge активен» создана собственным сценарием и не доказывает вызов WebAppVerifyMobileId. Источник: docs/protocol/mobileid-v0.1.23-failed-acceptance-2026-10-27.md.

## Шесть этапов выполнения и промежуточная приёмка
1. **Эталон по исходникам.** Восстановить точную последовательность: кнопка → серверный запуск мини-приложения → Mobile ID → сотовая сеть → запрос HTTP → результат JS → решение сервера. Для каждого звена указать подтверждённый факт, гипотезу и недостающие данные. Результат — схема обмена без вымышленных полей.
2. **Испытание на физическом Android.** Оригинальный MAX, тестовый аккаунт, исследовательская SIM, включённая мобильная передача данных; сравнить поведение с Wi-Fi. Установить, проходит ли операторская проверка и становится ли Android доверенным. Результат — подтверждённый рабочий эталон либо документированный отказ.
3. **Локальная связь MAX Desktop ↔ Android.** Начать с USB; отдельный компонент для согласованных тестовых действий и передачи состояний. Сначала воспроизвести взаимодействие на синтетических данных без секретов сеанса/оператора. Результат — работающее безопасное сопряжение, не выдаваемое за привязку устройства.
4. **Проверка серверной совместимости.** Установить, разрешает ли сервер продолжение настольной операции после действительного подтверждения на Android, или доверие связано строго с устройством/сеансом. При допустимости интегрировать; при недопустимости зафиксировать отрицательный результат, оценить отображение штатного Android-интерфейса на Windows только если защита экрана позволяет. Никакой имитации успешного оператора.
5. **Параллельная SMS-ветка.** На тестовом аккаунте с заранее включённой 2FA проверить реальную серверную процедуру «Привязать новое устройство» → SMS. Разделить случаи Госуслуг и других кодов. Не добавлять придуманную форму/запрос SMS.
6. **Интеграция и релиз.** Внедрить только экспериментально подтверждённый способ; сохранить несколько аккаунтов, рабочие авторизации, чаты, системный VPN/маршрутизацию и обновление. Выпуск после функциональной приёмки: настоящий код действительно показан в MAX Desktop после «Посмотреть код».

## Неизвестные, ограничения проверки
Не установлены: серверный алгоритм принятия доверия, привязка Mobile ID к устройству/сеансу, фактическое место вызова WebAppVerifyMobileId при v0.1.23, серверная применимость SMS для данного вида кодов и Windows, доступность вывода защищённого экрана Android.
Использовать только собственные тестовые аккаунты и исследовательскую SIM; не публиковать коды, авторизационные токены, подписанные адреса, идентификаторы сеанса, ответы оператора или переписку. Не менять действующий VPN и сохранённые сессии без отдельного основания. Не выпускать очередные предположительные исправления без доказательной проверки.
