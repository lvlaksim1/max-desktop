# MAX Desktop — мобильный сеанс и запрос доверенного устройства (27.10.2026)

## Приёмка владельца на v0.1.21
- После повторной авторизации клиент показывает `Протокол: TCP / Android / физическая сеть`.
- В ответе BOT_WEB_APP(160) для кнопки «Посмотреть код» URL содержит `WebAppPlatform=android`.
- Мини-приложение начинает загрузку (визуальный индикатор). По оценке пользователя загрузка занимает около 1–2 минут. После ожидания выводится «Для показа кода нужно привязать текущее устройство» и рекомендации о мобильном интернете, отключении Wi-Fi/VPN, а также совпадении номера SIM-карты с аккаунтом.
- Скрытые данные, номера, коды и подписанный URL **не сохранялись** в этом исследовании.

## Установленное
1. Предыдущие два расхождения WEB-транспорта и WebAppPlatform=web теперь отсутствуют. Сервер принимает текущий мобильный TCP-сеанс в обычных операциях и выдаёт запуск с `WebAppPlatform=android`.
2. Ограничение перешло в отдельную область доверенного устройства (проверка номера через мобильную сеть). Настольный клиент, даже с мобильным протоколом, не имеет физической SIM-карты/операторской сети, эквивалентной смартфону.
3. В коде `src/MaxDesktop.App/MiniAppWindow.cs` строка «Адрес выдан MAX...» задаётся при событии WebView2 `NavigationCompleted`. Поэтому вращающийся индикатор на пользовательском снимке появляется уже на странице мини-приложения, а не из-за блокировки первоначального HTTPS. Причина задержки 1–2 минуты **не определена**: возможно ожидание внутреннего запроса или серверной проверки; сетевых временных измерений по этапам нет.
4. Официальная процедура смены основного устройства MAX предусматривает Mobile ID, а при настроенной двухфакторной аутентификации — также подтверждение по СМС. См. https://help.max.ru/help/gosuslugi/svyazka_gosuslug_s_max/kak_smenit_doverennoe_ustroistvo_dlya_vhoda_v_gosuslugi .

## Решение менеджера
- Не менять VPN, маршрутизацию Windows или подписанный WebAppData, не подделывать признаки SIM/Mobile ID.
- Не выдавать подмену User-Agent за прохождение проверки доверенного устройства; не воспроизводить содержимое кодов подтверждения в диагностике.
- Штатное доверенное устройство владелец при необходимости привязывает в официальном мобильном приложении MAX со своей SIM.
- Для будущего анализа задержки можно добавить добровольную **локальную** безадресную диагностику времён `WebView2 initialization`, `NavigationCompleted` и `DOMContentLoaded`. Она не устанавливает продолжительность закрытых серверных запросов мини-приложения. Не логировать hostname, URL, fragment, query, токены, телефоны, коды, WebAppData.
- Не выпускать новую версию только ради изменения внешнего представления устройства. Последний пользовательски проверенный выпуск остаётся v0.1.21.
