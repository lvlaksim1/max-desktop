# MAX Desktop — запуск мини-приложений (26.10.2026)

В истории MAX GET_HISTORY(49) поле `attaches[]` может содержать `keyboard.buttons[][]` с типом `OPEN_APP`, полями `text`, `webApp`, `contactId`, `payload`. Такая запись клавиатуры не имеет маркера `_type`. Основание: https://github.com/pr0bel1230/max-api-docs/blob/main/protocol/messaging.md .

В MAX Desktop добавлен отдельный разбор клавиатур в Web JSON и MessagePack без изменения запроса истории и без вызова операций чтения/отправки. Кнопка показывается под сообщением и открывает указанный адрес только после явного нажатия пользователем.

При запуске `max.ru/<бот>` добавляется `startapp` и допустимый `payload` (если их ещё нет). Навигация разрешена только для HTTPS URL без встроенных учётных данных. WebView2 используется с изолированным профилем InPrivate, без доступа к токенам MAX, хост-объектам, веб-сообщениям и разрешениям устройств. Вкладки/новые окна сайта автоматически не открываются. Доступен явный переход в системный браузер.

**Граница приёмки:** это первый этап запуска веб-страницы мини-приложения. Настоящие подписанные данные `WebAppData` (в том числе `initData`, `hash` и `query_id`) не генерируются и не подделываются; внутренний мост MAX не воспроизведён. Поэтому приложения с серверной проверкой MAX-сессии могут не заработать, несмотря на успешную загрузку страницы. Реальная проверка конкретного Divan.ru и полноценной авторизации мини-приложения необходима отдельно.

Официальные сведения: https://dev.max.ru/docs/webapps/bridge и https://dev.max.ru/docs/webapps/validation .
