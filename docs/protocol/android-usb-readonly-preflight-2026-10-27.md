# Android USB: подготовительная проверка без вмешательства в MAX

Дата: 27.10.2026. Связанные вопросы: docs/plans/android-mobileid-desktop-integration-2026-10-27.md и docs/protocol/mobileid-v0.1.23-failed-acceptance-2026-10-27.md.

## Исходные наблюдения владельца
- На физическом смартфоне Android 15 уже успешно и без нового запроса привязки показан настоящий код в оригинальном MAX. На этом телефоне просмотр выполнялся и раньше; поэтому существует правдоподобная гипотеза о ранее доверенном устройстве. Новый вызов Mobile ID при этом **не подтверждён**. Снимок экрана оригинальный MAX не позволил сделать; не пытаться снимать защищённый экран.
- Команда `adb devices` вернула состояние `device` (авторизованная USB-отладка).
- `getprop ro.product.model` вернул модель `23049PCD8G`; Android 15; `pm list packages ru.oneme.app` подтвердил установленный оригинальный MAX.
- `dumpsys package ru.oneme.app` показал `versionCode=6879`, `versionName=26.36.2`. Прежнее статическое исследование в max-android-research охватывало APK 26.35.1 (6867).
- **Условная рабочая гипотеза по прямому указанию владельца:** считать необходимый механизм Mobile ID одинаковым в 26.35.1 и 26.36.2 до выявления противоречащих данных. Это инженерное допущение, **не результат сравнения исходников**.

## Средство проверки USB
`scripts/android-usb-preflight.cmd` — автономный командный файл Windows, требует только уже установленный `adb`, не требует PowerShell, не устанавливает ПО и не изменяет настройки Android.

Запуск в командной строке из каталога репозитория:
```cmd
scripts\android-usb-preflight.cmd
```
Или, если несколько ADB-устройств:
```cmd
scripts\android-usb-preflight.cmd СЕРИЙНЫЙ_НОМЕР
```

Читает только модель/версию Android, версию пакета ru.oneme.app, настроечные признаки `mobile_data`, `wifi_on`, `gsm.network.type` и проверяет двусторонний обмен **фиксированной искусственной строкой** `MAX_USB_BRIDGE_SMOKE_OK` через `adb shell echo`.

## Как трактовать результаты
- `USB ... PASS` означает, что команда запущена на Android и результат вернулся по USB. Это **не тест серверного Mobile ID**, не операторская проверка и не разрешение показать код на Windows.
- `mobile_data=1` — только настройка. Даже при `1` фактический трафик может идти через Wi-Fi; `gsm.network.type` — косвенный индикатор.
- Для следующего этапа потребуется отдельно определить, допускает ли сервер процедуру доверия в настольном сеансе. Нельзя делать вывод о переносимости из успешного USB-обмена.
- Скрипт не извлекает SMS, экран, ключи, токены, приватные ссылки или тела HTTP. Он также не меняет оригинальный MAX, рабочую привязку, VPN или сеть.
- Исследовательские данные не дают основания подделывать операторскую подпись, перенаправлять результат проверки или обходить запрет снимков защищённых кодов.

## Текущий статус
Инструмент сохранён в исходном репозитории; на подключённом физическом смартфоне пользователя **ещё не выполнен**. Проверка с настоящим Android требует запуска владельцем в командной строке Windows. Выпуск нового установщика MAX Desktop не производится на этом этапе.
