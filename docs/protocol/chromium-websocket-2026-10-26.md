# MAX Desktop: браузерный WebSocket без QR — диагностика 26.10.2026

## Подтверждённый сбой установленной версии v0.1.7

Согласно скриншотам владельца:
- TCP («мобильный протокол»): девять попыток через системный прокси и напрямую к трём серверам завершились TLS_HANDSHAKE / EOF до получения сертификата.
- .NET WebSocket («веб-протокол» и автоматический режим): попытка завершилась WS_CONNECT: WebSocketException. Предыдущий код скрывал внутреннюю причину (HTTP-код, сокет, TLS), поэтому нельзя считать определённой причину разрыва.
- Ни в одной из показанных попыток проверочный SMS-код не запрашивался: поле номера было пустым, пользователь нажимал только «Проверить соединение (без номера)».

Проверки на GitHub Windows успешно устанавливали те же соединения из **другого** сетевого окружения. Они не подтверждали доступность в сети владельца.

## Решение в v0.1.8

Не изменяя формат WEB-протокола MAX v11 и не используя QR, вынести сетевое соединение за интерфейс IMaxWebSocketChannel:
- DotNetMaxWebSocketChannel: прежний .NET ClientWebSocket с улучшенной диагностикой сетевых кодов и вложенных ошибок (без персональных значений).
- EdgeMaxWebSocketChannel: новый Chromium WebSocket через Microsoft.Web.WebView2 и собственную изолированную HTML-страницу. Для браузерного транспорта нет SslStream / ClientWebSocket .NET.
- WebView2 создаётся на UI/STA-потоке WPF и остаётся двухпиксельным элементом приложения. Виртуальный локальный документ доступен на https://web.max.ru/max-bridge.html; CSP не разрешает загрузку удалённых сценариев, а WebSocket допускается только для wss://ws-api.oneme.ru/websocket. Проверка сертификатов Chromium не отключается.
- Взаимодействие с .NET выполняется через CoreWebView2.PostWebMessageAsJson и WebMessageReceived, с проверкой документа-источника, меток сеанса и ограничениями размера пакетов. Токены сохраняются только в защищённом хранилище Windows (DPAPI); локальная HTML-страница не хранит их на диске.
- HybridMaxTransport предлагает «Автоматически (сначала Microsoft Edge)», «WebSocket через браузер Edge», «WebSocket через .NET», «TCP (мобильный протокол)». Автоматический переход между вариантами разрешён **лишь до возможной отправки SMS**, чтобы избежать повторных запросов кода.
- Сохранённые сеансы TCP и WEB восстанавливаются своим транспортом; сеанс Chromium отмечается WEB_EDGE. QR отсутствует.

**Зависимость:** Microsoft Edge WebView2 Runtime должен быть установлен в Windows. При отсутствии среды выводится диагностическое сообщение; приложение не устанавливает сторонний корневой сертификат и не отключает TLS.

## Проверки

- [GitHub Windows, 40255463057](https://github.com/lvlaksim1/max-desktop/actions/runs/40255463057): **успешно** установлено соединение через Chromium WebSocket с сервером MAX, получен ответ на анонимный INIT(6) без номера, SMS, QR или токенов.
- [GitHub Windows, 40255462997](https://github.com/lvlaksim1/max-desktop/actions/runs/40255462997): компиляция и прежние проверки WPF успешны.
- [GitHub Windows, 40255592968](https://github.com/lvlaksim1/max-desktop/actions/runs/40255592968): успешно пройдены тесты выбора транспорта, имитации SMS→код→LOGIN, проверки метки WEB_EDGE, проверка **неповторения SMS**, если ответ на первый запрос неизвестен, а также прежние испытания TCP и обновителя.

**Внешняя проверка анонимного INIT не является пользовательской приёмкой.** Настоящий SMS-запрос, ответ сервера, доставка SMS и окончательный вход с компьютера владельца ещё не подтверждены. Требуется тест «Проверить соединение (без номера)» в режиме «WebSocket через браузер Edge». При успехе — один запрос кода (без публикации номера, токена или кода). Параллельно остаётся необязательная диагностика предыдущих транспортов.
