# MAX Desktop — вход через WebSocket без QR (26.10.2026)

## Цель

Приёмка Windows MAX Desktop на машине владельца: прямые TCP/TLS-подключения к `api2.oneme.ru`, `api.oneme.ru`, `api-tg.oneme.ru` обрывались до получения сертификата даже с системным прокси. Это **не доказывает ошибку протокола авторизации**, но делает необходимым независимый транспорт.

Владелец **исключил QR-авторизацию**. Добавлен вход по номеру телефона через WEB/WebSocket как альтернативный путь, не меняя интерфейс и установку WPF.

## Проверенные независимые реализации

- [huxuxuya/python-max-client](https://github.com/huxuxuya/python-max-client), `python_max_client/client.py`: `wss://ws-api.oneme.ru/websocket`, заголовок `Origin: https://web.max.ru`, JSON-протокол версии 11. Методы `send_code` (opcode 17), `sign_in` (18), `login_by_token` (19), `_send_hello_packet` (6).
- [MaxApiTeam/PyMax](https://github.com/MaxApiTeam/PyMax): отдельный `WebSocketTransport`, `WsProtocol`; реализация последовательности SMS/пароль/токен и сохранения сеанса.
- [Tellarion/webmaxsocket](https://github.com/Tellarion/webmaxsocket): вход по SMS и 2FA, альтернативные транспорты. QR не используется в MAX Desktop.

## Архитектура

- `MaxWebSocketCodec`: в отличие от TCP, отправляет JSON `{ver:11,cmd:0,seq,opcode,payload}`.
- `NativeMaxWebSocketTransport`: `ClientWebSocket` с системным прокси, проверкой TLS MAX, Origin и User-Agent; `INIT(6)` → `START_AUTH(17)` → `CHECK_CODE(18)` → при необходимости пароль `115` → `LOGIN(19)`. Запросы сериализованы, ответ сопоставляется с `seq`/`opcode`; нет ложного входа, если сервер не подтвердил LOGIN.
- `HybridMaxTransport`: выбор «Автоматически / WebSocket / TCP». При автоматическом входе сначала WebSocket; TCP может использоваться как резерв **только если WebSocket не установил соединение или не прошёл анонимный INIT**. После отправки запроса SMS автоматический повтор через другой транспорт запрещён.
- `MaxSavedSession.Transport`: новая необязательная метка `WEB`/`TCP`. Старые хранилища без поля продолжают использовать TCP. Токен хранится с прежней шифровкой Windows DPAPI.
- QR-подтверждение **не реализовано**.

## Проверки

- [GitHub Actions 40253115470](https://github.com/lvlaksim1/max-desktop/actions/runs/40253115470): Windows-исполнитель подтвердил защищённое WebSocket-подключение и серверный ответ `SESSION_INIT` **без номера, кода, QR и токенов**.
- `tests/MaxDesktop.WebSocket.Smoke`: протокол JSON v11, SMS-пакет, обработка ошибок, обратная совместимость сохранённых сеансов и выбор транспорта без сети.
- Windows CI компилирует WPF и запускает все протокольные и файловые тесты. Тесты не отправляют проверочные SMS.
- Реальная доставка кода по номеру и завершение авторизации с конкретного компьютера владельца **не подтверждены**. Сервер может потребовать капчу или альтернативную проверку; приложение не выдаёт ложный успех.

## Поведение приложения Windows

- Крестик главного окна — `Hide()` и работа в трее, без закрытия приложения или потери сеанса.
- Системная кнопка «Свернуть» — обычное сворачивание в панель задач.
- Двойной щелчок по значку трея — восстановление окна.
- Правый щелчок по трею — «Открыть MAX Desktop» и «Выход», явный выход освобождает ресурсы.
- Межпроцессный Mutex + сигнал активации: повторный запуск не создаёт второй экземпляр; открывает существующий.
- Обновитель использует явное завершение, которое обходит обработчик «крестик в трей». Иначе установленное обновление могло бы зависнуть в ожидании работающего процесса.

## Непроверенные функции

- Успешный запрос SMS на живом номере, условия капчи, 2FA и полный вход.
- Синхронизация чатов и отправка сообщений.
- Фактическое взаимодействие кнопок трея на пользовательской Windows; компиляция не заменяет графическую приёмку.
