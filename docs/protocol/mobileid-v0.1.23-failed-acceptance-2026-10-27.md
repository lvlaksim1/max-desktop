# MAX Desktop — несостоявшаяся приёмка Mobile ID / SMS на v0.1.23

Дата: 27.10.2026. Статус: **не работает**, новый релиз без доказанного исправления не выпускать.

## Фактическая приёмка

Пользователь установил v0.1.23. На двух снимках mini-app проходит через вращающийся индикатор к сообщению «Проверяем номер телефона» / «Это необходимая настройка безопасности». Строка в заголовке mini-app: «Интерфейс MAX Bridge активен. Запрос Mobile ID пока не получен». Реальная форма подтверждения SMS не появляется; защищённый код не показан.

## Установленная ошибка в интерпретации

`src/MaxDesktop.App/MiniAppWindow.cs` вызывает `AddScriptToExecuteOnDocumentCreatedAsync`. Внедрённый нами скрипт сразу после создания `WebViewHandler`/ `PrivateWebViewHandler` отправляет в собственный хост `miniapp-bridge-ready`, который делает `_bridgeReady = true`.

**Эта отметка доказывает только выполнение внедрённого скрипта в верхнем документе с заданным origin; не доказывает, что JavaScript мини-приложения использовал мост.** Утверждать, что мост MAX работает, по ней нельзя.

Отметка `_mobileIdRequestSeen` нигде не появилась: наш обработчик не получил `WebAppVerifyMobileId`. Код `client.verify_mobile_id.no_cellular` поэтому вообще не был отправлен в MAX. Две предыдущие версии v0.1.22/v0.1.23 исправляли предположительный путь, не подтвердив, что mini-app его вызывает.

Номер аккаунта передаётся в `MiniAppWindow` исключительно для отображения, не участвует в `WebAppVerifyMobileId`. По исследованному оригинальному APK Android 26.35.1 модель запроса содержит `requestId` и `url`; отдельного телефонного номера нет.

## Неустановленные причины (не выдавать за факты)

1. Мини-приложение использует иной канал или не вызывает `WebAppVerifyMobileId` на рассматриваемом экране.
2. Сценарий запускается в iframe, другом HTTPS origin или перенаправлении: текущая инъекция имеет фильтр `window === window.top` и `location.origin === signedOrigin`.
3. Мини-приложение выполняет серверную проверку до вызова моста либо не имеет подтверждения серверных условий для SMS.
4. Конкретный способ через SMS из [документации MAX](https://help.max.ru/help/gosuslugi/svyazka_gosuslug_s_max/kak_smenit_doverennoe_ustroistvo_dlya_vhoda_v_gosuslugi) описан для сообщений Госуслуг и установленного заранее пароля 2FA. Он не доказан для всех защищённых кодов и ПК.

## Следующий допустимый технический этап

Не повторять выпуск косметических сборок. Сначала воспроизвести интерфейсы мини-приложения в изолированном локальном тесте и различить:
- внедрение собственного скрипта и фактическое обращение страницы к его методам;
- документ верхнего уровня, перенаправления и дочерние кадры (без сохранения signed URL);
- запросы `WebAppVerifyMobileId` и отсутствие таковых;
- наличие серверной (а не самостоятельно нарисованной) СМС-формы.

Исследовательские измерения, если нужны, ограничить числом кадров и событиями/таймингами без тела ответов, токенов, куки, веб-адресов подписанных запусков, телефонных номеров, запросов/ответов оператора и самих кодов.

**Критерий готовности функциональности:** подлинный код действительно появляется в MAX Desktop после одобренной сервером проверки; **ни один из опубликованных релизов этого пока не подтвердил**.

Рабочие сохранённые аккаунты и системный VPN не менять.
