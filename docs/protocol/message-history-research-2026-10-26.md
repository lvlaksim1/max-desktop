# MAX Desktop — исследование GET_HISTORY (26.10.2026)

Источник: https://github.com/pr0bel1230/max-api-docs/blob/main/protocol/messaging.md#get_history-opcode-49

## Подтверждённый формат
Запрос GET_HISTORY opcode 49: `chatId`, `backward`, `forward`, `backwardTime`, `forwardTime`, `getChat`, `from` (UNIX timestamp в миллисекундах), `getMessages`, `interactive`. Ответ `messages` — массив с `id`, `time`, `type`, `sender`, `text`, `attaches` и дополнительными полями. Некоторые типы сообщений могут не содержать обычного текста.

Для получения последних 30 сообщений использовать `from=now_ms, backward=30, forward=0, backwardTime=0, forwardTime=0, getChat=false, getMessages=true, interactive=false`. `backward>0` без `from` может вернуть пустой результат. Следующая страница — по времени самого старого сообщения предыдущей; аккуратно устранять граничные дубликаты.

## Правила реализации
- Историю загружать только при явно выбранном чате, защищённо обрабатывать ошибки сервера, переключение чатов и отмену запросов.
- Разбирать уникальные идентификаторы сообщений, время, отправителя и текст; направление сообщения (своё/чужое) определять только при достоверном ID собственной учётной записи.
- Не сохранять личные переписки в публичных GitHub Actions, Issues или логах.
- Не вызывать CHAT_ACTIVITY(92), который по описанию может изменять watermark. Не отмечать сообщения прочитанными автоматически на этапе чтения истории.
- Сейчас GetMessagesAsync в MAX Desktop ещё является заглушкой. Ни история, ни её приёмка пока не выполнены; выпуск v0.1.15 остаётся актуальным.
