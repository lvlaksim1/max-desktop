# MAX Desktop — Android LTE: проверены сотовые сетевые возможности
Дата: 27.10.2026. Статус: **измерено на физическом Android через доверенный PC Gateway**.

## Источник, метод и воспроизводимость
- Реальный смартфон пользователя: Android 15, установлен официальный MAX 26.36.2 (6879); ранее USB/ADB префлайт проверен PASS.
- Тест выполнялся через штатный подключённый PC Gateway из репозитория `lvlaksim1/pc-runner-gateway`, по разрешённому маршруту `repo.powershell`.
- Использован зафиксированный на SHA `ddf59ece0fe5b84c9fabf4db0a7b025dedf6cc5c` сценарий `.pc-gateway/tasks/Inspect-AndroidCellularNetwork.ps1`, читающий `adb shell dumpsys connectivity`.
- Проверка извлекает сетевые возможности только из записей `NetworkAgentInfo` и не принимает наличие одного `NetworkRequest` за наличие реальной сети.
- Результат завершённого запроса: [PC Gateway issue #491](https://github.com/lvlaksim1/pc-runner-gateway/issues/491), Windows workflow 40433281714 (успешная стадия выполнения).
- Ранее первый запуск [#489](https://github.com/lvlaksim1/pc-runner-gateway/issues/489) подтвердил исполнение и разбор, но шлюз показал лишь `observations_collected`; скрипт изменён так, чтобы публиковать **только безопасные агрегаты** в статусе.

## Фактические результаты
```text
network_observation:
  agents=3
  parsed=3
  cellular=3
  cellular_internet=2
  cellular_internet_validated=2
```
Таким образом, снимок системного состояния Android содержит **как минимум две записи сетевых агентов** с возможностями `TRANSPORT_CELLULAR`, `NET_CAPABILITY_INTERNET` и `NET_CAPABILITY_VALIDATED`. Значения отражают записи вывода ConnectivityService, **не количество SIM-карт или физических модемов**. Дополнительно ранее `mobile_data=1`, `wifi_on=0`, `gsm.network.type=LTE,LTE`.

Этот набор соответствует запрашиваемым в анализе APK 26.35.1 Mobile ID возможностям:
```java
new NetworkRequest.Builder().addTransportType(0).addCapability(12).build()
```
Где Android 0 = CELLULAR, 12 = INTERNET. По требованию владельца считаем этот механизм одинаковым в текущем MAX 26.36.2, **как рабочее допущение, а не результат сопоставления бинарных версий**.

## Доказательность и оставшиеся задачи
**Доказано:** (а) компьютер умеет обмениваться командами с Android через USB; (б) система Android сообщает сотовые сети, предоставляющие интернет и прошедшие проверку подключения. Сетевая предпосылка оригинального `WebAppVerifyMobileId` выполнена по текущему наблюдению.

**Не доказано:** (а) исходный MAX запрашивал Mobile ID на **уже доверенном** устройстве при повторном открытии кода; (б) отправлял HTTPS запрос оператору; (в) сервер принимает подтверждение для отдельного настольного сеанса; (г) защищённый код показан в MAX Desktop. Команда не вызывала Mobile ID и не изменяла доверие.

**Следующий рациональный шаг:** изучить, какие переходы на стороне мини-приложения/сервера и какие признаки вызовов можно наблюдать без сброса доверенной привязки. Затем проверить разрешённое сопряжение Android↔Windows либо настоящую SMS-ветку, если сервер её предложит. Не подменять операторские ответы, не обходить запрет снимков и не считывать значения защищённых кодов.

## Защита данных
В результате публикуются только агрегаты возможностей. Сценарий не сохраняет полный `dumpsys`, IP-адреса, номера телефона, токены, код, содержимое экранов и ответы мобильного оператора. Программа MAX, авторизации, устройство и сетевые параметры оставлены без изменений.
