# MAX Desktop — вход в аккаунт через нативный протокол

Дата: 26.10.2026. Исходный образец: APK ru.oneme.app 26.35.1 (6867), SHA-256
e809176d6bf6ff69247274433ec170a5db8a5687a02a04299a78a2ae978119fc.

## Что реализовано

1. Прямое TCP/TLS-соединение к api2.oneme.ru:443, проверка сертификата Windows.
2. Двоичное кадрирование версии 10: 10-байтовый заголовок, MessagePack и распаковка LZ4.
3. SESSION_INIT (6): deviceId, mt_instanceid, параметры устройства, получение callsSeed.
4. Вычисление 96-байтового отпечатка сеанса из метаданных APK, callsSeed и deviceId.
5. AUTH_REQUEST (17): запрос кода по телефону с mode.
6. AUTH (18): проверка кода, извлечение tokenAttrs.LOGIN.token.
7. Проверка дополнительного пароля (115), если сервер вернул passwordChallenge.
8. LOGIN (19): вход по токену, подтверждение положительного ответа сервера.
9. Защита токена с помощью DPAPI пользователя Windows и восстановление сохранённого сеанса.
10. PING (1), ограничение размеров пакетов, тайм-ауты, явные ошибки без записи токенов.

**Состояние:** подготовлена реализация и автоматические проверки кодеков. Успешный вход под реальным аккаунтом MAX пока не подтверждён.

## Известные ограничения

- Если MAX предлагает подтверждение **звонком**, выводится явное сообщение о неподдерживаемой процедуре.
- Регистрация нового аккаунта пока не реализована.
- Чаты, отправка и получение сообщений не подключены.
- Ответы со сжатием Zstandard пока не поддерживаются.
- Пока хранится только один авторизованный сеанс.
- Автоматические проверки не доказывают совместимость с работающим сервером; возможен отказ из-за ограничений или изменений MAX.
- Сборочные испытания не отправляют реальные номера, SMS-коды или ключи.

## Приёмка

1. Обновиться с установленной версии кнопкой «Обновить».
2. Ввести свой номер телефона через «Добавить аккаунт».
3. Проверить, возвращён ли код или альтернативный способ подтверждения.
4. Ввести код в локальном окне; если запрошен дополнительный пароль — указать его там.
5. При успехе перезапустить приложение и проверить восстановление сеанса.
6. При ошибке сообщить **этап, текст ошибки и время**. Не публиковать свой номер, проверочный код, пароль, токен или полные необезличенные пакеты.

## Физический маршрут для нативного Android TCP в v0.1.13 (26.10.2026)

Уточнение владельца: официальный Android-клиент MAX авторизуется без капчи и 2FA; WEB v11 нашего клиента получил требование установить 2FA при opcode 18. Это **разные протоколы и потенциально разные контексты доверия**; не доказано, что новая мобильная сессия нашего клиента будет принята без дополнительных проверок.

Для APK `ru.oneme.app 26.35.1` ранее реализованы бинарный TCP v10, MessagePack/LZ4, SESSION_INIT(6), AUTH_REQUEST(17), CHECK_CODE(18), LOGIN(19). Ранее мобильный транспорт шёл через системную сеть и сталкивался с TLS EOF при работающем Xray/TUN. В Issue [PC Gateway #404](https://github.com/lvlaksim1/pc-runner-gateway/issues/404) физический IPv4 ПК владельца успешно провёл TLS с проверенным сертификатом для `api2.oneme.ru`, `api.oneme.ru` и `api-tg.oneme.ru`.

В v0.1.13 добавлен отдельный `TcpPhysical` в HybridMaxTransport, `NativeMaxTransport(bindPhysicalInterface:true)`, физическая привязка только IPv4/без системного HTTP-прокси, при сохранении TLS/SNI. В сеансе сохраняется транспортный тип `TCP_PHYSICAL` для последующего восстановления. Выбор нового режима ручной; веб-автоматическое подключение и защита от повторных SMS неизменны.

[GitHub Actions #40345635857](https://github.com/lvlaksim1/max-desktop/actions/runs/40345635857) подтверждает реальный `SESSION_INIT` через новый C# транспорт на Windows Runner. [Сборка #40345636022](https://github.com/lvlaksim1/max-desktop/actions/runs/40345636022) и [релиз #40346233767](https://github.com/lvlaksim1/max-desktop/actions/runs/40346233767) успешны. Единственный опубликованный выпуск — v0.1.13, два установщика и SHA256.

Дальнейшая приёмка: анонимный INIT установленного v0.1.13 на ПК владельца, затем отдельная попытка SMS/LOGIN. Не заявлять успешную мобильную авторизацию до реального положительного ответа сервера. Настройки VPN не изменять.

## Первый полноценный пользовательский LOGIN (26.10.2026)

На аккаунте без настроенного пароля MAX Android требует установить «Пароль для входа» на уже активном устройстве для подключения второго устройства; сам Android блокирует установку на сутки. Это политическое/временное ограничение сервера, не дефект SMS или TLS.

На другом аккаунте с уже установленным паролем MAX Desktop запросил и проверил SMS-код и дополнительный пароль, а затем показал «MAX подключён». В коде успешный LOGIN сопровождается выдачей токена, его защищённой DPAPI-записью и состоянием Connected. Владелец подтвердил это скриншотом установленной v0.1.13. По изображению невозможно доказать, какой именно транспорт был выбран, и отдельно не проверено восстановление после перезапуска.

В текущем MainWindow список чатов не загружается, так как GetChatsAsync/GetMessagesAsync возвращают пустые списки, а SendMessageAsync ещё не реализован. Следующий протокольный этап — реальные опкоды синхронизации списка чатов, истории и отправки. Не считать пустой список ошибкой авторизации. Последний выпуск с исправлением закрытия LoginWindow — v0.1.14, CI 40349627306, публикация 40349627377; пользовательский тест v0.1.14 ожидается.
