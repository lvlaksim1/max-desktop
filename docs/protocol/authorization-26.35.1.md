# MAX Desktop — вход в аккаунт через нативный протокол

Дата: 26.10.2026. Исходный образец: APK ru.oneme.app 26.35.1 (6867), SHA-256
e809176d6bf6ff69247274433ec170a5db8a5687a02a04299a78a2ae978119fc.

## Что реализовано

1. Прямое TCP/TLS-соединение к api2.oneme.ru:443, проверка сертификата Windows.
2. Двоичное кадрирование версии 10: 10-байтовый заголовок, MessagePack и распаковка LZ4.
3. SESSION_INIT (6): deviceId, mt_instanceid, параметры устройства, получение callsSeed.
4. Вычисление 96-байтового отпечатка сеанса из метаданных APK, callsSeed и deviceId.
5. AUTH_REQUEST (17): запрос кода по телефону с mode.
6. AUTH (18): проверка кода, извлечение tokenAttrs.LOGIN.token.
7. Проверка дополнительного пароля (115), если сервер вернул passwordChallenge.
8. LOGIN (19): вход по токену, подтверждение положительного ответа сервера.
9. Защита токена с помощью DPAPI пользователя Windows и восстановление сохранённого сеанса.
10. PING (1), ограничение размеров пакетов, тайм-ауты, явные ошибки без записи токенов.

**Состояние:** подготовлена реализация и автоматические проверки кодеков. Успешный вход под реальным аккаунтом MAX пока не подтверждён.

## Исходные файлы

- src/MaxDesktop.Protocol/MaxMessagePack.cs — кодер и декодер MessagePack.
- src/MaxDesktop.Protocol/MaxTcpFraming.cs — TCP-пакеты, LZ4.
- src/MaxDesktop.Protocol/MaxAndroidFingerprint.cs — отпечаток APK.
- src/MaxDesktop.Protocol/NativeMaxTransport.cs — TLS, авторизация, пароль и восстановление.
- src/MaxDesktop.App/ProtectedMaxSessionStore.cs — защищённое хранение.
- src/MaxDesktop.App/LoginWindow.xaml — окно входа.
- tests/MaxDesktop.Protocol.Smoke — автономные проверки.

Параметры отпечатка относятся к APK 26.35.1 и не должны смешиваться с другими сборками.

## Известные ограничения

- Если MAX предлагает подтверждение **звонком**, выводится явное сообщение о неподдерживаемой процедуре.
- Регистрация нового аккаунта пока не реализована.
- Чаты, отправка и получение сообщений не подключены.
- Ответы со сжатием Zstandard пока не поддерживаются.
- Пока хранится только один авторизованный сеанс.
- Автоматические проверки не доказывают совместимость с работающим сервером; возможен отказ из-за ограничений или изменений MAX.
- Сборочные испытания не отправляют реальные номера, SMS-коды или ключи.

## Приёмка

1. Обновиться с установленной версии кнопкой «Обновить».
2. Ввести свой номер телефона через «Добавить аккаунт».
3. Проверить, возвращён ли код или альтернативный способ подтверждения.
4. Ввести код в локальном окне; если запрошен дополнительный пароль — указать его там.
5. При успехе перезапустить приложение и проверить восстановление сеанса.
6. При ошибке сообщить **этап, текст ошибки и время**. Не публиковать свой номер, проверочный код, пароль, токен или полные необезличенные пакеты.
